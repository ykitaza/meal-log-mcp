# 食事記録 MCP（meals）の設計

チャット（Claude / ChatGPT）で写真か一言を送るだけで、食事を記録できるようにします。
基盤（認可API、Cognito、CDK、Lambda）の上に、境界づけられたコンテキスト「食事記録」として `services/meals/` を置きます。

## 決めたこと

- **画像は MCP クライアント（Claude・ChatGPT）が解析し、MCP サーバーは記録だけ**をします。サーバー側では AI を呼びません
- **画像は保存しません**。AI が写真から読み取った説明文（`description`）を保存します
  - Claude には、チャットに貼った画像をツールに渡す公式の方法がありません（Claude のコネクタのドキュメントには、ツールから画像を返す方法だけが書かれています）
  - ChatGPT は `_meta["openai/fileParams"]` で `{download_url, file_id, mime_type, file_name}` を渡せます（未検証）。あとで `record_meal` に写真の引数を足せる作りにしておきます
  - MCP Apps のファイル機能は「未実装」です（ext-apps の移行ガイド）
- **CRUD** のツールをそろえます
- **言葉でも記録できます**（写真と同じ扱い）。あとからまとめて記録してもかまいません
- **食事の区分**（朝食・昼食・夕食・間食）を持ちます。時刻が分かれば時刻から、分からなければ指示か料理の内容から決めます
- **記録の前に、チャットで1回だけ確認します**（「この内容で記録してよいですか？」）。確認はこの一言だけで、ほかの質問（調味料など）はしません。確認はチャットの中だけで行い、サーバーには下書きの状態を持ちません。保存したあとの間違いは `update_meal` で直します
  - ツールの説明に「推定した内容を利用者に見せ、了承を得てから `record_meal` を呼ぶ」と書きます
  - 「いつもの」「昨日と同じ」、数値だけの記録は、中身が分かっているので確認なしで記録します
- **写真をまとめてアップロード**する使い方に対応します（下の節）
- 守れたかどうかで責めません（連続記録の表示はしません）。外食は概算で記録してかまいません

## 主要アプリの調査から取り入れるもの

| 取り入れる点 | 元のアプリ |
|---|---|
| 推定結果を食材ごとの行で返し、1行ずつ直せる | MacroFactor（Plate） |
| ~~見えない材料（油・ソース・調味料）を1問だけ確認する~~ 採用しない（質問を増やさないため） | Cronometer |
| 守れたかどうかで評価しない、週4日以上・概算の記録でよい | MacroFactor（adherence-neutral） |
| カロリー・PFC の数値だけで記録 | MacroFactor、MyFitnessPal（Quick Add） |
| 前日のコピー、いつものセット | あすけん、MyFitnessPal |
| 筋トレの日と休みの日で目標を変える。たんぱく質は体重×1.6〜2.2g の固定値 | MacroFactor、MyFitnessPal、Cronometer |

写真は各社とも「推定の入力」として使っており、記録と一緒に残すと明記している例はありませんでした。
Cronometer は写真日記（ノートへの添付）を AI 記録と別の機能にしています。カロミルはカメラロールの直近72時間の食事写真を自動で解析します。
利用者の不満としては、写真推定の誤差（油・ソースの見落とし、量の誤り）、写真機能の有料化、連続記録による罪悪感、記録疲れが挙がっていました。

## ドメインモデル

### 言葉

| 言葉 | 型 | 意味 |
|---|---|---|
| 食べた人 | `EaterId` | 記録の持ち主。認可の `sub` から `EaterResolver` で変換する |
| 食事 | `Meal`（集約） | 1回の食事 |
| 品目 | `FoodItem`（`Meal` の中のエンティティ） | 「白米 200g」などの1行 |
| 栄養 | `Nutrition`（値） | kcal、たんぱく質、脂質、炭水化物（g）。0以上、足し算と倍数ができる |
| 量 | `Quantity`（値） | 数と単位（g、ml、個、杯） |
| 確かさ | `Confidence`（値） | 推定の確かさ（高・中・低） |
| 区分 | `MealSlot`（値） | 朝食・昼食・夕食・間食。時刻から決めるときは 朝食 5〜10時、昼食 10〜15時、夕食 17〜22時、それ以外は間食（仮の境目、変更可） |
| 食べたとき | `EatenOn`（値） | 日付と区分（必須）、時刻（分かれば）。写真の撮影日時は Claude には渡らないため、時刻なしでも記録できる |
| 記録の仕方 | `Source`（値） | 写真の推定／文字／数値だけ／複製／いつもの |
| いつもの | `MealTemplate`（集約） | 名前を付けて保存した組み合わせ。`to_meal(eaten_at)` で食事を作る |
| 目標 | `NutritionGoal`（集約、食べた人ごとに1つ） | 方針（増量・減量・維持）、体重、筋トレの日と休みの日の `DailyTarget`、`protein_per_kg` |
| 食事の傾向 | `EatingStyle`（値、`NutritionGoal` が持つ） | 自炊・外食・コンビニのどれが多いか。次の食事の候補を出すときに使う |
| 日の種類 | `DayType` | 筋トレの日／休みの日 |
| 体重 | `WeightRecord`（日付ごとに1つ） | 30〜300kg。目標体重までの進み具合（`GoalProgress`）は、直近28日の記録から週の変化を計算して出す |

### Meal（集約）

- 持つもの：`eaten_on`（`EatenOn`）、`items`、`description`、`source`
- 記録した時点で確定します。状態は持ちません
- 操作：`total()`、`change_amount(行, 量)`（栄養も同じ割合で変わる）、`add_item`、`remove_item`、`move_to(EatenOn)`
- 品目は `Meal` を通してだけ変えます

### まとめ（集約ではなく計算して出す）

- `DailySummary`：その日の食事の合計、目標（日の種類で選ぶ）、残り
- `WeeklyReview`：記録した日だけの平均。「7日中5日記録」と出しますが、責めません

### ポート

`MealRepository`、`MealTemplateRepository`、`GoalRepository`、`DayTypeRepository`、`WeightRepository`、`EaterResolver`。
今は入れていませんが、あとで `FoodDatabase`（検証済みの食品データとの照合）を足せる形にしています。

## ツール（MCP）

| ツール | 内容 |
|---|---|
| `record_meal` | 品目・日付・区分・時刻（任意）・説明文で記録 |
| `record_meals` | まとめて記録（写真をまとめて貼ったとき） |
| `get_meal`、`list_meals` | 読む（期間・区分で絞れる） |
| `update_meal` | 品目の量の変更・追加・削除、日時・区分の変更 |
| `delete_meal` | 消す |
| `copy_meal` | 昨日と同じ |
| `save_template`、`record_template` | いつもの |
| `goal_questions` | 目標を決めるために聞く項目（選択肢・必須・初期値）。必須は方針だけ |
| `suggest_goals` | 答えた項目から目標の案を計算する（保存はしない） |
| `set_goals`、`set_day_type` | 目標と日の種類 |
| `today_status` | 今日の合計・残り（記録のたびに返す） |
| `weekly_review` | 週の平均と目標との差 |
| `record_weight`、`goal_progress` | 体重を記録する、目標体重までの進み具合 |
| `logout` | 連携を解除する（間違えたアカウントでログインしたとき） |

チャットでの流れの例：写真か一言 → AI が推定して表で見せ「この内容で記録してよいですか？」（まだ保存しない）→「OK」（直したいところがあれば一緒に言う）→ `record_meal` →「記録しました。今日のたんぱく質 あと42g」

## 写真をまとめてアップロードしたとき

撮影日時（EXIF）は Claude には渡りません（Claude の web 版で試して確認しました）。そのため、日付と区分は次の順で決めます。

1. 一言の指示（「昨日の分」「朝・昼・夜」）をいちばん優先します
2. 指示がなければ、日付は今日、区分は料理の内容と貼った順番から AI が推測します
3. 時刻は分からなければ持ちません

推定した全件を1つの表（日付・区分・料理・kcal・P）で見せ、1回の了承で `record_meals` を呼びます。
同じ日・同じ区分にすでに記録があるかは、見せる前に `list_meals` で確かめ、表に「すでに記録があります」と出します（同じ写真を2回貼る失敗への対策）。
将来 ChatGPT から元のファイルを受け取れる場合は、EXIF の撮影日時から日付と時刻を決めます。場所（GPS）は使いません。

## 目標と食事の傾向は、食べた人ごとに決める

目標の方針（増量・減量・維持）、体重、食事の傾向（自炊・外食・コンビニ）は、アプリに決め打ちしません。食べた人ごとに `set_goals` で決めます。
まだ決めていない人には、`today_status` が「目標が未設定です」と返し、AI がその場で質問して `set_goals` を呼びます（最初の1回だけ）。

## 目標は方針だけ必須

性別・年齢・身長・体重・筋トレは、答えたくない人もいます。必須は方針だけにし、分かっている項目だけで出せる目標を出します。

- 方針だけ：数字の目標はなし（今日の合計と週の平均だけ）
- ＋体重：たんぱく質の目標
- ＋身長・年齢・普段の活動量：kcal・脂質・炭水化物の目標（Mifflin-St Jeor）。性別を答えないときは、定数を男女の中間（−78）にします
- ＋筋トレの時間：筋トレの日の kcal を増やします（なければ休みの日と同じにします）

目標はサーバーが計算し、AI に数字を考えさせません（`suggest_goals`）。
聞き方（フォーム）は ChatGPT・Claude に任せます。`goal_questions` が聞く項目（選択肢・必須・初期値）を返し、ChatGPT や Claude は自分のフォームや選択肢のカードで聞きます。

## 見せ方は AI に任せる

MCP Apps で作った画面（目標のフォーム、今日・週・目標までの進み具合のダッシュボード）は、やめました。
ツールはデータ（JSON）と次の提案（`suggested_next`）だけを返し、フォーム・表・グラフ・ボタンは ChatGPT・Claude に任せます。
見せ方の方針（数字は表やグラフで、PFC は割合とグラムの両方、週は日ごとの推移）は、サーバーの instructions で伝えます。

やめた理由は次のとおりです。

- ChatGPT では、こちらのフォームと ChatGPT のフォームが2つ並びました
- 画面からチャットに文を送ると、Claude が警告を出します
- ホストが画面の HTML を使い回すので、直しても届きにくくなります
- 見た目はホストに合わせたほうが自然です
